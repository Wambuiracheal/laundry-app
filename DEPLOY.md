# Deploying Panda Laundry

| Part | Host | What runs there |
| --- | --- | --- |
| Database | [Supabase](https://supabase.com) | PostgreSQL |
| API | [Render](https://render.com) | `server/` (Express + Prisma), from [`render.yaml`](render.yaml) |
| Web app | [Netlify](https://netlify.com) | `client/` (Next.js), from [`netlify.toml`](netlify.toml) |

Do the steps in this order: the API needs the database URL, the web app needs the API URL, and the API's CORS setting needs the web app's URL.

Never commit `.env` files or keys. Every secret below goes into the Render or Netlify dashboard only.

---

## 1. Database on Supabase

1. Create a project at supabase.com. Save the database password somewhere safe. Pick the region closest to your users that matches the Render region in `render.yaml` (Frankfurt, `eu-central-1`, is the default there).
2. Open **Connect** (top of the project page) and copy two connection strings. Replace `[YOUR-PASSWORD]` in both; if the password has symbols such as `@`, `#` or `/`, URL-encode them (`@` becomes `%40`).
   - **Transaction pooler** (port **6543**). Add `?pgbouncer=true&connection_limit=1` to the end. This is `DATABASE_URL`.
   - **Session pooler** (port **5432**). This is `DIRECT_URL`, which migrations use.

   Don't use the "Direct connection" string. It is IPv6-only and Render can't reach it.

You don't need to create any tables. The API runs `prisma migrate deploy` every time it starts, and that creates the schema.

## 2. API on Render

1. Push the repository to GitHub.
2. On Render: **New > Blueprint**, pick the repository. Render reads `render.yaml` and creates the `panda-laundry-api` web service.
3. Fill in the values it asks for:

   | Variable | Value |
   | --- | --- |
   | `DATABASE_URL` | Supabase transaction pooler string (with `?pgbouncer=true&connection_limit=1`) |
   | `DIRECT_URL` | Supabase session pooler string |
   | `CLIENT_URL` | Leave empty for now; you'll set it in step 5 |
   | `MPESA_CONSUMER_KEY`, `MPESA_CONSUMER_SECRET`, `MPESA_PASSKEY` | From the Daraja portal (sandbox for now) |
   | `MPESA_CALLBACK_BASE_URL` | This service's URL, e.g. `https://panda-laundry-api.onrender.com`. If you don't know it yet, set it after the first deploy. |
   | `FIREBASE_*` | Optional; damage photos stay off until set (see `server/.env.example`) |

   `TOKEN_SIGNING_SEED`, `SESSION_SECRET` and `MPESA_CALLBACK_SECRET` are generated by Render automatically.
4. Deploy. When the logs show `Laundry backend is listening`, open the service URL: it should say **Laundry API is running!**

## 3. Load services and create the admin

The new database is empty. From your computer, point the seed script and `create-user` at Supabase using the **session pooler** string for both variables.

PowerShell:

```powershell
cd server
npm install
$env:DATABASE_URL = "<session pooler string>"
$env:DIRECT_URL   = "<session pooler string>"
npm run seed
node scripts/create-user.js --email you@example.com --password 'Str0ng!Pass' --role admin
Remove-Item Env:DATABASE_URL, Env:DIRECT_URL
```

Git Bash / macOS / Linux:

```bash
cd server && npm install
export DATABASE_URL="<session pooler string>" DIRECT_URL="<session pooler string>"
npm run seed
node scripts/create-user.js --email you@example.com --password 'Str0ng!Pass' --role admin
unset DATABASE_URL DIRECT_URL
```

Staff and rider accounts can be made the same way (`--role staff`, `--role rider`). Riders can also sign up at `/register/rider`.

## 4. Web app on Netlify

1. On Netlify: **Add new site > Import an existing project**, pick the repository. `netlify.toml` already sets the base directory (`client`), build command and Node version.
2. Under **Site configuration > Environment variables**, add:

   | Variable | Value |
   | --- | --- |
   | `NEXT_PUBLIC_API_BASE_URL` | The Render URL, e.g. `https://panda-laundry-api.onrender.com` (no trailing slash) |

3. Deploy. You'll get a URL such as `https://panda-laundry.netlify.app`.

`NEXT_PUBLIC_API_BASE_URL` is built into the site, so after changing it, trigger a new deploy (**Deploys > Trigger deploy**).

## 5. Lock the API to the web app

Back on Render, set `CLIENT_URL` to the Netlify URL (e.g. `https://panda-laundry.netlify.app`, no trailing slash; comma-separate several, such as a custom domain). Save; Render redeploys. From then on, browsers only accept API responses on your site.

## 6. First-time setup in the app

1. Open the Netlify site and log in as the admin.
2. **Riders** page: set the **shop location** (search and pick the address). Delivery fees, rider pay and directions all depend on it.
3. **Pricing** page: check the service prices.
4. Place a test order as a customer to check the whole flow.

## Things to know

- **Render free plan sleeps** after about 15 minutes without traffic, and the first request after that can take up to a minute. M-Pesa results that arrive while it's waking are still picked up, because the app also checks payment status itself. A paid plan avoids the sleep.
- **Supabase free projects pause** after a week without activity; resume them from the dashboard.
- **Redis is optional.** Without it the API skips caching and event publishing. To add it, create a Render Key Value instance and set `REDIS_URL`.
- **Maps and addresses** use free OpenStreetMap services (map tiles, Photon search, OSRM routing) meant for light use. For heavy traffic, use a commercial tile provider and set `OSRM_URL` / `PHOTON_URL` to self-hosted instances.
- **Rider GPS** works on the Netlify site because it is HTTPS. Browsers block location on plain `http://` pages other than localhost.
- **Going live with M-Pesa:** switch `MPESA_ENV` to `production` and use your production shortcode, passkey and keys from Daraja.
- **Existing local data** is not copied to Supabase. Only the services (seed) and the accounts you create in step 3 exist at first.

## Troubleshooting

| Symptom | Likely cause |
| --- | --- |
| API logs `Can't reach database server` | Wrong connection string, or the direct (IPv6) string was used. Use the pooler strings. |
| `prepared statement "s0" already exists` | `DATABASE_URL` is missing `?pgbouncer=true`. |
| Browser console: blocked by CORS policy | `CLIENT_URL` on Render doesn't exactly match the site URL (scheme, no trailing slash). |
| Site calls `localhost:5000` | `NEXT_PUBLIC_API_BASE_URL` wasn't set before the Netlify build. Set it and redeploy. |
| Everyone signed out after each restart | `TOKEN_SIGNING_SEED` isn't set on Render. |
| Delivery fees stay "pending" | The shop location isn't set (step 6). |
